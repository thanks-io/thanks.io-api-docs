---
title: 'Scan Board Stage Change'
description: 'Event will fire whenever a card on your QR Scan Board enters the stage the webhook is set to.'
---

<Note>
Scan Board stage webhooks are available on the Business plan and up.
</Note>

## When it fires

Each webhook of type `scan_board.status_update` is tied to one Scan Board stage, set in `scan_board_status`: `new`, `contacted`, `follow_up` or `done`. It fires when a card enters that stage, including when a newly scanned mailer lands in **New**.

Each webhook fires at most once per card per stage. Moving a card out of a stage and back in doesn't send it again. Scans already on your board when the Scan Board launched don't fire webhooks.

You can add one from **Settings → [Webhooks](https://dashboard.thanks.io/app/settings/webhooks)**, from a column on the Scan Board, or with the [Create Webhook](/api-reference/endpoint/webhooks/create-webhook) endpoint:

```json
{
    "url": "https://example.com/webhooks/thanksio?name=~FIRST_NAME~",
    "type": "scan_board.status_update",
    "scan_board_status": "contacted",
    "verb": "post"
}
```

## Personalized URLs

The webhook URL can include replacement variables such as `~FIRST_NAME~` or `~CUSTOM1~`. They're filled in with each lead's details when the webhook is sent.

## Scan Board fields

The payload carries the same order item fields as other order item events, plus:

| Field | Description |
|---|---|
| `scan_board.card_id` | The ID of the card on your Scan Board. |
| `scan_board.previous_status` | The stage the card left. `null` for a new card. |
| `scan_board.current_status` | The stage the card entered. |
| `scan_board.last_scanned_at` | When the mailer was last scanned. |
