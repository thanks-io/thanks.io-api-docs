The thanks.io MCP server lets an AI assistant work in your thanks.io account. Once it is connected, you can ask in plain language and the assistant does the work with the tools listed on this page:

- **Send real mail.** Postcards, windowed and windowless letters, notecards, magnacards and gift cards, to saved mailing lists or addresses you give it.
- **Preview and price first.** Every order can be rendered as proof images with its exact total before anything is charged.
- **Design.** Use your saved creatives and templates, or have ThanksAI Studio draw a new front design from a description.
- **Build audiences.** Create mailing lists and add recipients.
- **Track results.** Check printing and delivery, QR code scans and gift card redemptions, see which designs, messages and lists perform best, and find out whether a person or address was mailed.
- **Automate.** Create recurring campaigns and turn them on or off, and set up webhooks that send events to your other systems.

The server is a remote MCP server at:

```text
https://mcp.thanks.io/mcp
```

<Note>
  This is a different server from the [Documentation MCP Server](/mcp-server) at `https://docs.thanks.io/mcp`. The documentation server only searches these docs and cannot read your account or send mail. Use the server on this page to work with your account.
</Note>

## Before You Start

You will need:

- A [thanks.io account](https://dashboard.thanks.io/register)
- An AI assistant that supports remote MCP servers over HTTP, such as Claude, ChatGPT, Gemini, Claude Code, Cursor or GitHub Copilot in VS Code

## How It Connects

### Sign in with OAuth (recommended)

Most assistants need only the server URL. When you add it, the assistant opens a thanks.io sign-in page; sign in and approve access, and you are connected. There is no API key to copy or paste.

The server supports OAuth 2.0 with dynamic client registration, so assistants register themselves automatically. You do not need to create an OAuth application in your dashboard first.

### API key (fallback)

If an assistant cannot sign in on its own, connect with an API key sent as a bearer token:

1. In your dashboard, open **Settings → [API & MCP Access](https://dashboard.thanks.io/app/settings/api-access)**.
2. In the **API Keys** section, click **Create API Key**, name it, and leave **Allow MCP access** turned on.
3. Copy the key. It is shown only once.
4. Configure your assistant to send it in the `Authorization` header:

```json
{
  "mcpServers": {
    "thanksio": {
      "url": "https://mcp.thanks.io/mcp",
      "headers": { "Authorization": "Bearer YOUR_API_KEY" }
    }
  }
}
```

A key created without **Allow MCP access** is refused by the MCP server. Treat an MCP-enabled key like a password: anyone holding it can act on your account, and can send mail once orders are allowed (see below).

## Spending Permissions

Connecting an assistant does not let it spend money. Two settings under **Settings → [API & MCP Access](https://dashboard.thanks.io/app/settings/api-access)**, in the **MCP Permissions** section, decide what it may pay for. Both start off.

| Setting | What it allows |
|---|---|
| **Allow orders via MCP** | Placing real, paid mail orders with the send tools, and turning on a recurring campaign. |
| **Allow lead purchases via MCP** | Paid address lookups: finding a postal address for a recipient given only an email address. |

Without them, an assistant can still check results, plan, design, save templates and creatives, build mailing lists from full addresses, and preview orders. When it needs a permission you have not turned on, the tool is refused, nothing is charged, and the assistant tells you which setting to switch on.

<Warning>
  Once **Allow orders via MCP** is on, your assistant can send real mail. Orders are charged to your credit balance or card and cannot be recalled once printing starts. Gift card orders are also charged the face value of every card. The server instructs assistants to show you a preview with the total and wait for your confirmation before every send, so read the preview before you approve. Turning on a recurring campaign authorizes every send it will make on its schedule.
</Warning>

## Set Up Your Assistant

The quickest way is to ask your assistant to set itself up. Paste this into the assistant you use:

```text
I'd like to connect you to my thanks.io account so you can help me with direct mail. thanks.io has a remote MCP server at https://mcp.thanks.io/mcp that uses OAuth sign-in, so no API key is needed. Walk me through adding it as a connector or MCP server in the app I'm using to talk to you right now, one step at a time. If this app can't connect to remote MCP servers, tell me which apps can.
```

Or follow the steps for your assistant. Menu names can change as these apps update.

## What to Ask

Some examples to start with:

- "How is my mail doing? Which of my postcards gets the most QR scans?"
- "Send my open house postcard to the Austin Sellers list. Show me the proof and the total first."
- "Design a postcard for a spring HVAC tune-up special, then save it as a creative."
- "Set up a birthday card campaign for my Clients list, but leave it paused."

## How Sends Work

The server guides every assistant through the same steps before any mail goes out:

1. Pick the audience: a saved mailing list, or addresses you provide.
2. Pick what to print: usually a saved creative from your creatives library, or a front design and a message.
3. Preview the order with `preview-order`, which renders proof images and calculates the exact total without charging anything.
4. Show you the proofs and the total, and wait for your confirmation.
5. Send with the matching send tool.

After saving a design, placing an order or creating a campaign, the assistant gives you a link to review it in your dashboard, where you can also cancel an order that is still under review.

To act for one of your sub-accounts, ask the assistant to use that sub-account. It finds the sub-account with `list-sub-accounts` and passes its `sub_account_id` to the other tools.

### Audience

| Tool | What it does |
|---|---|
| `list-mailing-lists` | Your mailing lists and their sizes. |
| `create-mailing-list` | Create a new mailing list. |
| `add-recipient` | Add one recipient to a mailing list. |
| `add-recipients` | Add many recipients to a mailing list at once. |
| `list-recipients` | The recipients on a mailing list, with deliverability status. |

### Preview then send

| Tool | What it does |
|---|---|
| `preview-order` | Render proof images and calculate the total for an order, without charging anything. |
| `send-postcard` | Send postcards. |
| `send-letter` | Send letters in a windowed envelope. |
| `send-windowlessletter` | Send letters in a windowless envelope. |
| `send-notecard` | Send folded notecards in an envelope. |
| `send-magnacard` | Send magnacards with a tear-off magnet. |
| `send-giftcard` | Send gift cards. Charged for the mailing and the face value of each card. |

The send tools need **Allow orders via MCP**. A recipient given an email address but no street address needs **Allow lead purchases via MCP**, for `preview-order` and the send tools as well as `add-recipient` and `add-recipients`. To send without those lookups, the assistant can pass `email_lookup: false`, which leaves out recipients who have no street address.

`preview-order` and the send tools also take:

- `postage_class`: `first_class` or `standard`. See [Postage Class](/api-reference/send-mailer-usage#postage-class).
- `return_address_id`: one of your saved return addresses, listed by `get-account-info`, in place of typing a return address.
- `realism`: turn handwriting realism on or off for this order.

On the Free and Business plans, `preview-order` proof images carry a **DRAFT** watermark. The mail you send prints without it.

### Order lifecycle

| Tool | What it does |
|---|---|
| `list-orders` | Recent orders with status, cost and QR scan counts. |
| `get-order` | Printing and delivery status, returns, QR scans and gift card redemptions for one order, or for up to 50 orders at once. |
| `get-order-stats` | Spend, delivery, scans and redemptions over a date range, for the whole account or narrowed to one campaign, creative or mailer type. |
| `list-order-recipients` | Everyone an order actually mailed, page by page. |
| `search-order-recipients` | Whether a person or street address was mailed by any of your orders, and by which. |
| `cancel-order` | Cancel an order that is still under review. Orders that have started printing cannot be cancelled. |

A mailing list shows who is on it now; `list-order-recipients` and `search-order-recipients` show who was actually mailed, which is what you need to check a contact against your CRM. Gift card codes are never returned.

How you pick a prompt depends on your assistant; many show them in a menu or as slash commands.

## What Each Tool Can Change

Every tool is in one of three groups, by what it can do to your account. Each tool also carries MCP's read-only or destructive hint, which assistants use to decide when to ask you before running it.

### Read

These only read your account. They never change, charge or send anything.

`get-account-overview`, `get-performance`, `get-marketing-playbook`, `get-account-info`, `list-sub-accounts`, `list-handwriting-styles`, `list-image-templates`, `list-message-templates`, `list-giftcard-brands`, `list-creatives`, `get-creative`, `get-studio-design`, `list-studio-designs`, `list-mailing-lists`, `list-recipients`, `list-orders`, `get-order`, `get-order-stats`, `list-order-recipients`, `search-order-recipients`, `list-webhooks`, `list-campaigns`

### Write

These change your account, but never charge you or send anything outside thanks.io.

| Tool | What it changes |
|---|---|
| `create-image-template`, `update-image-template` | Saves or changes a front design. Updating replaces the design's name or image. |
| `create-message-template`, `update-message-template` | Saves or changes a message. Updating replaces its text or settings. |
| `create-creative`, `update-creative` | Saves or changes a creative. |
| `create-studio-design`, `refine-studio-design`, `update-studio-design` | Creates or changes a ThanksAI Studio design. Designing is free. |
| `save-studio-design-templates` | Saves a Studio design as templates and a creative. |
| `create-mailing-list` | Creates an empty mailing list. |
| `create-campaign` | Creates a recurring campaign, paused. Nothing is sent until it is turned on. |
| `cancel-order` | Cancels an order that is still under review. |
| `delete-webhook` | Stops a webhook. |

### Sensitive write

These can spend money or send recipient data outside thanks.io, so the assistant should confirm each one with you. The spending ones are refused until you turn on the setting in the last column.

| Tool | What it does | Needs |
|---|---|---|
| `send-postcard`, `send-letter`, `send-windowlessletter`, `send-notecard`, `send-magnacard` | Places a paid order, charged to your credit balance or card. Mail can't be recalled once printing starts. | **Allow orders via MCP** |
| `send-giftcard` | Places a paid order as above, also charged the face value of every card. | **Allow orders via MCP** |
| `set-campaign-active` | Turning a campaign on authorizes every send it makes on its schedule, with no further preview. Pausing one is always allowed. | **Allow orders via MCP** to turn on |
| `preview-order`, `add-recipient`, `add-recipients` | Buys an address lookup for each recipient given an email address but no street address. With full addresses they charge nothing. | **Allow lead purchases via MCP** for lookups |
| `create-webhook`, `update-webhook` | Sends recipient names and addresses to the webhook's URL every time its event happens. | A paid plan |

### When a Tool Is Refused

A refused call returns a message saying why, and nothing is charged:

- **Missing permission.** The message names the setting and links to it.
- **Invalid input.** The message says which field is wrong.
- **Duplicate order.** The same order placed again within two minutes is refused, and the message gives the first order's id. A retried call never prints or charges the same mail twice.
- **Too many orders.** Over 10 orders in a minute, a send is refused and the message says how many seconds to wait.
- **Charge failed.** If the billing charge fails, or the chosen mailing lists have no deliverable recipients, the order is not placed.

An unexpected error returns a reference code to quote to [support@thanks.io](mailto:support@thanks.io).

A placed order's result includes its status and total charged. `get-order` then reports printing and delivery, and `cancel-order` works only while the order is still under review.

### Try It Without Sending

Turn on **Test Mode** under **Settings → [API & MCP Access](https://dashboard.thanks.io/app/settings/api-access)**, in the **API Settings** section. The send tools still need **Allow orders via MCP**, but each order is created already cancelled: nothing is charged, printed or mailed, and the tool's result says so. `preview-order` and `get-account-info` report test mode too. Test mode does not make address lookups free, so leave **Allow lead purchases via MCP** off while testing. See [API Testing Mode](/api-reference/api-mode).

## Limits

The MCP server accepts up to 120 requests per minute per account, and places at most 10 orders per minute per account across all the send tools. A request over a limit is refused and can be retried after a minute. Orders refused for invalid input don't count toward the order limit.

## Disconnecting

To disconnect an assistant, remove the connector or MCP server in the assistant's own settings. If you connected with an API key, delete the key under **Settings → [API & MCP Access](https://dashboard.thanks.io/app/settings/api-access)** to revoke it.
